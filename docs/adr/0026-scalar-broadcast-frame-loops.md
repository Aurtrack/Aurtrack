# 0026 标量广播与帧循环操作数特化

## 状态

已接受并实施。Repeat 累加器不再把帧不变值写成 64 元素数组，帧循环按
“操作数来自标量还是数组”生成专用循环；128 同时音符 2 秒离线渲染从
1.50–1.88 秒降到 1.09–1.17 秒，实时系数 0.89 → 0.55。

后续：ADR 0027 用可关闭的 AVX2 + FMA 四路内核把 `sin`/`exp` 与帧循环
算术向量化，128 同时进一步降到 0.68–0.71 秒。

## 背景

ADR 0025 把 `sin`/`exp` 换成多项式并去掉了帧循环的逐帧边界检查，但明确
留下两项开销：每个 SSA 值的分派，以及帧不变值的 `fill`。复测 128 同时
音符（release、48kHz、64 帧 block、2 秒）时，`RepeatAccumulator::accumulate`
占整次渲染约 75%（1.37 秒 / 1.82 秒）；在累加器内部：

| 组成 | 耗时 | 说明 |
| --- | --- | --- |
| 标量 `evaluate` + `fill` | 约 0.9 秒 | 18 个帧不变值 × 12 次迭代 |
| 三路 `sin` | 约 0.6 秒 | 每 partial 每帧 3 次 |
| 一路 `exp` | 约 0.35 秒 | 每 partial 每帧 1 次 |

数据由临时探针与消融模式取得（临时改 `repeat.rs`，未提交）：标量分支的
`fill` 单项约 0.55 秒，`evaluate` 约 0.38 秒，`sin` 约 0.60 秒，`exp` 约
0.35 秒；各项不严格可加，因为去掉一个瓶颈后其他项会暴露出来。

物理钢琴的 `piano.partial` body 有 74 个 SSA 值：37 个与迭代无关（每块
只算一次），37 个与迭代有关；后者在默认计划里 18 个是帧不变标量、19 个
真正逐帧。按块算，128 声部每个 block 有 481 次值求值，其中 216 次是
“标量求值 + `fill` 64 个 f64”。

## 决定

### 标量掩码

进入迭代循环前，用与原先相同的判定算出一次 `scalar_mask`：

```text
scalar = !depends_on_time && (external_mask & !const_mask) == 0
```

`depends_on_time` 与 `external_mask` 都在编译期沿参数传播，所以标量值的
所有参数必然也是标量；反过来，只要有一个参数依赖时间或逐帧外部输入，
这个值就一定不是标量。这条不变量让标量求值可以完全不读逐帧数组。

### 标量栈

`scalars: [f64; MAX_LOOP_VALUES]` 是 `accumulate` 里的栈数组，按值下标
存放标量结果；帧不变值只做一次 `evaluate_scalar` 并写进这里，不再
`fill` 数组。`evaluate_scalar` 用切片模式匹配取出参数，逐个算子镜像
`SsaOp` 的标量内核；参数个数不匹配时返回 0.0（构建器不会产生这种值）。

### 帧循环按操作数特化

`evaluate_frames` 新增 `scalars` 与 `scalar_mask` 参数，逐个算子只保留
操作数组合对应的循环：

- 二元算子：标量×标量、标量×数组、数组×标量、数组×数组；
- 一元算子：标量（直接 `fill` 结果）、数组；
- `Sine`：时间逐帧时，再按频率与相位是否为标量分四份；时间、频率、相位
  全是标量时直接 `fill`；
- 罕见的组合（时间是常量但频率/相位逐帧；`Clamp`/`MapRange`）用逐帧
  取操作数的通用循环，不在热路径上。

循环体内的每次访存因此都是确定的：标量进寄存器，数组才走切片，没有
逐帧分支。

### 逐位一致

改动只改变操作数“从哪里读”，浮点运算的序列与顺序完全不变：

- 标量值仍由同一套 `SsaOp` 语义计算，`evaluate_scalar` 与旧的
  `evaluate(.., frame=0)` 逐算子对应；
- `Sine` 保持 `(TAU · frequency) · time + phase` 的左结合顺序，频率是
  标量时 `TAU · frequency` 只是被提前算好，数值相同；
- 没有重结合、没有相位递推、没有新的近似函数。

因此 block 输出与改动前逐位相同，不涉及任何 AB 误差阈值。

### 不新增运行时资源

`scalar_mask` 与 `scalars` 都是栈数组，大小由 `MAX_LOOP_VALUES` 固定；
没有新增堆分配、锁或日志。scratch 仍是编译期分配的
`Vec<[f64; 64]>`，只是帧不变值不再写它，实际工作集从约 38 KB 降到
约 10 KB（L1 常驻）。

## 性能

同一台机器、release、48kHz、64 帧 block、2 秒离线渲染。改动前取
ADR 0025 记录的区间与本轮首次基线（128 同时 1.79 秒），改动后连测六次
（下表为区间；系统调度噪声约 ±8%）：

| 场景 | 改动前 | 改动后 | 实时系数（前 → 后） |
| --- | --- | --- | --- |
| 32 同时 | 0.40–0.44s | 0.282–0.311s | 0.20–0.22 → 0.14–0.16 |
| 64 同时 | 0.78–0.93s | 0.545–0.665s | 0.39–0.46 → 0.27–0.33 |
| 128 同时 | 1.50–1.88s | 1.092–1.170s | 0.75–0.94 → 0.55–0.59 |
| 300 顺序 | 0.60–0.97s | 0.443–0.525s | 0.30–0.49 → 0.22–0.26 |

- 128 同时稳定在 1.2 秒以内，比本轮基线（1.79 秒）快约 38%，距离 2 秒预算还有
 约 0.8 秒余量；64 同时的实时系数降到 0.3 附近，不再接近 deadline。
- `block_deadline_report`（8/12 音，每轮回调独立计时）：8 音 p99 111µs、
  最大 138µs；12 音 p99 164µs、最大 257µs（另一次 12 音最大 184µs）；预算 1333µs，
  `over_1ms == 0`、`over_5ms == 0`、整块回退为 0。ADR 0025 记录的 p99
  是 194–571µs，本轮整体下移。
- 收益来源：帧不变值的 `fill` 与其后的数组读一起消失（约 0.55 秒），
  标量求值不再走“读 74 项数组 + 双重边界检查”的旧路径（约 0.38 秒），
  帧循环少一次数组读、工作集进入 L1。`sin`/`exp` 仍是最大单项，合计约
  0.9 秒，本轮不动。

## 已知限制

- `sin` 仍是 128 同时的主要成本（约 0.6 秒）：LLVM 依然没有把这些
  循环向量化，x86-64 基线的 SSE2 双精度只有 2 lane。显式 SIMD 或
  固定 64 长度的特化是下一步；相位递推仍未采用，因为需要先证明
  block 与逐采样在任意起始位置一致。
- 标量求值（约 0.38 秒）仍按块重算。这些值只依赖音高、力度、外部常量
  与迭代序号，理论上可按“音符槽 + 输入签名”跨块缓存；本轮不引入这份
  状态，避免 seek/混合起始语义与零分配约束变复杂。
- `const_mask` 每块仍会扫描最多 32 个外部槽位；这是纯启发式判断，成本
  已低于它节省的逐帧计算，暂不优化。
- 罕见的 `Sine` 组合（时间常量、频率或相位逐帧）和 `Clamp`/`MapRange`
  的逐帧形式走通用循环，比专用循环慢；它们不在物理钢琴的默认计划里。
- 累加器仍不做跨迭代公共子表达式消除；body 的 37 个迭代不变值每块只算
  一次，但同一迭代内重复的子表达式依赖构建器的 CSE。
