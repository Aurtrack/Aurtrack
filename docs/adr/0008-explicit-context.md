# ADR 0008：执行上下文必须显式

- **状态：** 已接受
- **日期：** 2026-11-01
- **决策者：** 项目维护者

## 背景

一次真实漏声暴露了问题：轨道里有一个未接到输出的 `Piano Voice` 组，播放计划仍然扫描它并生成全局钢琴声部；另一个被命名为“静音”的节点读取了这个全局声部，于是声音从没有显式连线的路径漏到输出。

这不是单个节点的 bug，而是**隐式上下文**：

- 执行依赖的状态没有出现在端口、字段或连接里。
- 编译器通过“第一个匹配节点”或“任意节点扫描”推断当前执行环境。
- UI 标签、节点名字或轨道里碰巧存在的节点，改变了实际声音。

之前清理过 Note/Gate 的隐式输入，但“没有隐式上下文”这个结论下得太早。只要还存在从全局扫描推断执行上下文，这个结论就不成立。

## 决策

### 1. 执行上下文必须能从文档模型直接读出

音源、声部、组实例、Note 来源、默认值和全局计划，必须满足至少一条：

- 是节点的显式端口或连接。
- 是实体的显式字段，保存进工程文件。
- 是编译计划中带稳定 ID 的显式槽位。
- 是协议规定的全局上下文，且有 schema、文档和测试，例如 transport、sample rate。

不能依赖“第一个匹配”“最后一个匹配”“节点名字”“UI 当前选择”。

### 2. 音源和声部不得从任意扫描推断

- 不允许用 `nodes().find(|node| node.is_instrument())` 决定唯一音源。
- 不允许扫描任意 `audio.group` 是否存在 Note 输入来决定全局钢琴声部。
- `GraphOp::Voice` 必须绑定到明确的 instrument/group 槽位，不能读取一条轨道共享的隐藏 voice。
- 一个组实例的声音只能由它自己的输出连接贡献；未接输出的组不得影响其他节点。

### 3. 默认值是 schema 默认值，不是隐藏上下文

- 未连接端口使用 socket 声明里的默认值是允许的，因为默认值属于端口 schema。
- “找不到音源就猜第一个”“找不到组就用全局组”“静音节点复用 Voice”不是 schema 默认值，禁止。
- 静音乐器必须输出 0，不能借用全局 voice。

### 4. UI 显示不能改变执行语义

- 自定义 `label` 只影响显示，不参与音源、类型或执行判断。
- 节点标题必须能看出实际类型，不能让“静音”标签掩盖 Piano/Sine 类型。
- 旁通、静音、未连接、隐藏节点之间必须有明确且一致的语义。

### 5. 允许的显式轨道级上下文

以下上下文可以存在，但必须写进 schema 和测试：

- 轨道自身的 clips/notes。
- transport 的播放位置、tempo、sample rate。
- 命令事务和撤销栈。

它们不能反过来改变某个节点的音源类型，除非通过显式字段或端口。

## 当前审计清单

| 位置 | 隐式行为 | 状态 |
| --- | --- | --- |
| `Track::source` | 取第一个 instrument 决定音源 | 已修：`Track.source` 显式节点引用 |
| `Track::playback_graph` | 扫描任意 `audio.group` 的 Note 输入生成全局 piano | 已修：只从 `Track.source` 读取 |
| `GraphOp::Voice` | 所有 Voice 节点共享轨道级 voice | 已修：只有 `Track.source` 指向的组编译 Voice |
| ADSR/plugin 选择 | 扫描任意节点取 ADSR/插件 | 已修：只接受输出路径上的节点 |
| 多个 plugin | 播放计划 last-wins | 已修：图校验拒绝多个 plugin |
| 多个 ADSR | 包络计划 last-wins | 已修：音频图校验拒绝多个 ADSR |
| `audio.instrument.silence` | 曾编译为 Voice，透传全局声部 | 已修 |
| 节点 mute | 旁通与静音语义混用 | 已修 |
| Zone 边界 | header 承载外部端口，CLI/UI 不一致 | 已修 |
| clips/notes | 轨道级上下文 | 允许；需明确文档 |
| transport | 全局上下文 | 允许；需 schema |

审计结论：上表中的禁止路径已经清零；clips/notes 和 transport 作为显式声明的轨道级/全局上下文保留。新增执行上下文必须先进入本表。

复查补充：`Track.source` 是显式文档字段，不是图端口，按本 ADR 合规定义成立；如果要求“所有音源都必须由端口连接决定”，它仍不满足，需要改成专用 source 节点。`audio.instrument.silence` 输出的是 Audio 类型的 0 值，不是隐藏 voice。

后续：ADR 0010 已删除 `Track.source`，改为从输出反向收集所有活乐器。

## 强制手段

1. `AGENTS.md` 架构红线增加“禁止隐式上下文”。
2. 代码审查优先搜索：`find(|node|`、`group_id`、`GraphOp::Voice`、`source()`、`unwrap_or(第一个)`。
3. 回归测试统一以 `explicit_context_` 开头，覆盖：
   - 未接输出的 Voice 组不得发声。
   - 静音节点不得透传任何 voice。
   - 多组/多乐器不得共享隐藏状态。
4. 新增执行上下文时，先更新 ADR 或本清单，再写代码。

## 非目标

- 不要求所有值都必须接线；schema 默认值仍然合法。
- 不要求把 transport、sample rate 变成节点端口。
- 不为了“显式”而拆掉轨道级 clips/notes 模型。

## 后果

短期会增加编译计划的参数和测试；长期避免“改一个无关节点，声音从另一条路径漏出来”的问题。
