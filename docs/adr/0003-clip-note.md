# ADR 0003：clip/note 模型与工程格式 v2

- **状态：** 已接受
- **日期：** 2026-10-20
- **决策者：** 项目维护者

## 背景

v1 的轨道只有一个连续信号源：正弦或静音。四轨叠加能听出和弦，但没有音符、时值和力度，不能真正演奏。时间线也只是把连续源画成一条通栏块。

下一步需要让一个片段容纳多个音符，并让引擎按时间调度它们。

## 决定

### 1. 数据模型

- `Track` 增加 `clips: Vec<Clip>`。
- `Clip` 有 `id`、`name`、`start`、`duration`、`notes`。
- `Note` 有 `id`、`pitch`（MIDI 0–127）、`start`（相对片段）、`duration`、`velocity`（0–1）。
- 时间单位统一为秒；v1 时间线固定 5 秒，片段与音符必须落在 `0..=5` 内。
- 连续信号源保留：现有 sine 轨道继续作为 drone；音符轨用 `silence` + clips。

### 2. 命令

新增六条命令，全部走命令总线并支持撤销：

- `clip.create` / `clip.update`：建片段，修改名称、起点、长度。
- `clip.remove`：按路径删片段。
- `note.add` / `note.update`：加音符，修改音高、位置、长度、力度。
- `note.remove`：按路径删音符。

时间线和钢琴卷帘的拖动/缩放通过 `clip.update` / `note.update` 落库；复制粘贴、量化、自动化不在本次范围内。

### 3. 引擎调度

- 播放计划里的每条轨道增加 `notes`，每项包含绝对起点、时值、频率、力度。
- 音频回调按当前播放时间判断音符是否活跃，叠加到轨道信号上。
- 连续源与音符可以同时存在；音符轨通常把源设为静音。
- 离线渲染使用同一套音符规则，保证试听与导出一致。

### 4. 工程格式

- `format_version` 升到 `2`；`Track.clips`、`Clip.notes`、`Note.velocity` 都是必填字段。
- 打开只接受 v2；旧文件直接拒绝。在维护者明确提出兼容要求前，不做迁移、不加 serde 默认值。
- 打开时校验片段/音符 ID、时间范围、音高、力度与唯一性，并重建 `next_clip` / `next_note`。

## 后果

- 一个片段里可以有多个音符，引擎按时间调度，和弦和旋律才是真的。
- 当前工程还没有真实用户，旧文件不兼容；等有明确要求时再设计迁移，避免维护无用的兼容代码。
- 时间线仍是固定 5 秒；等需要长工程时再加 `length_seconds` 与循环区域。
- 复制粘贴、量化、自动化、片段重叠策略不在本次范围内。
