# ADR 0002：工程文件使用带版本的 UTF-8 JSON

- **状态：** 已接受
- **日期：** 2026-10-20
- **决策者：** 项目维护者

## 背景

现在工程只存在于 `Session` 的内存里，重启就丢。继续加 clip、音符、自动化之前，必须先有一个稳定的持久化格式，否则每次改模型都要迁移旧数据。

工程文件还要同时满足三个使用方：桌面 UI、CLI、MCP。格式必须是人类可读、可 diff、可被 AI 直接读写的。

## 决定

### 1. 文件格式

- 扩展名：`.aurtrack.json`
- 编码：UTF-8 JSON，不压缩
- 顶层结构：

```json
{
  "format_version": 1,
  "project": {
    "name": "demo",
    "sample_rate": 48000,
    "tracks": []
  }
}
```

- `format_version` 是整数，当前为 `1`。
- `project` 只存文档数据，不存播放位置、音频设备、master gain、UI 状态。
- 写入使用 pretty JSON，方便 diff 和人工检查。

### 2. ID 与寻址

- 轨道 ID 必须是 `track-{n}`，设备 ID 必须是 `device-{n}`，`n` 从 1 开始。
- ID 在文件内唯一；设备 ID 在整个工程内唯一。
- 打开时校验 ID，并重建 `next_track` / `next_device`，避免新实体和旧 ID 撞车。
- 不满足命名规则的工程文件直接拒绝，不做静默修复。

### 3. 命令语义

- `project.save`：把当前工程写到调用方给的路径，不产生撤销快照。
- `project.open`：读取并校验文件，成功后才替换当前工程，可撤销。
- 路径由调用方提供：桌面用原生文件对话框，CLI / MCP 直接传路径。
- v1 不做自动保存和崩溃恢复，后续再补。

### 4. 版本与迁移

- `format_version` 不匹配时拒绝打开，并返回明确错误。
- 新字段必须伴随版本号提升；打开旧版本时由迁移函数升级，不允许猜测字段。
- v1 不实现迁移，只接受版本 `1`。

## 后果

- 工程文件可读、可 diff，AI 可以直接生成和修改。
- 不需要引入二进制容器或数据库；当前规模用 JSON 足够。
- 大工程、采样、插件状态以后可能需要二进制附件，届时在 v2 里单独设计，不混进 v1。
- 每次模型变更都要考虑 `format_version` 和迁移，这是长期成本，但比“重启丢工程”便宜得多。
